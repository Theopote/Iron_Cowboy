# Project STEPPE 后续开发路线图

## 当前起点

工程基线为 P13.2：“骑乘 → 马群 → 切出 → 投索 → 控绳 → 捕获登记 → 下马接近 → 第一次接触 → 牵回营地 → 命名”已经可玩，套索技巧、失控后果、双地表反馈路由和 Horse Card 层级已经接入，并有 18 项自动化测试及实际渲染回归。路线图接下来继续填充正式表现资源与动画。

里程碑编号从 **P9** 延续现有工程历史；它不等同于早期讨论稿的阶段编号。

## P9 — 捕获后安全接近

**状态：已完成。** 实现与验证记录见 `P9_CAPTURE_AFTERMATH_SPEC.md`。

**目标：** 捕获不再是按钮后的终点，玩家需要下马并让目标接受第一次接触。

范围：

- 将 Captured 结果拆分为 Controlled、Approaching、Trusted/Captured 等可解释状态。
- 目标读取玩家距离、步行速度、正面冲入和停顿时间。
- 过快靠近会让目标后退、增加压力或暂时拒绝接触；缓慢靠近和适时停顿降低压力。
- 使用上下文交互完成第一次触摸，并记录最低限度 Trust 结果。
- HUD 给出行为提示，视觉实现可继续使用灰盒。

退出条件：

- 玩家不能在马上或高速冲向目标时直接完成信任。
- 至少存在一条可恢复的接近失败路线。
- 自动化测试覆盖速度/距离/停顿规则，实际试玩完成捕获后下马接近。

## P10 — 牵回营地与命名

**状态：已完成。** 实现与验证记录见 `P10_LEAD_DELIVERY_NAMING_SPEC.md`。

**目标：** 完成早期设计定义的第一条完整情感闭环。

范围：

- 建立 Lead 状态和牵引锚点；目标通过 Horse Intent 与 Movement 跟随。
- 增加营地/围栏交付区域和明确返回方向。
- 交付后显示 Horse Card：临时身份、性别/年龄占位、毛色、三到四项能力与性格词。
- 支持输入名字、确认本轮结果和开始新一轮。
- 本轮内保存命名结果；跨启动持久存档另行立项。

退出条件：

- 玩家无需控制台或调试操作即可完成营地出发到命名。
- 牵行目标不会瞬移、穿越主要障碍或重新加入活动马群。
- 重玩会清理旧任务对象；命名界面不会与骑乘输入冲突。

## P11 — 可感知的马匹个体差异

**状态：已完成。** 实现与验证记录见 `P11_HORSE_ARCHETYPES_SPEC.md`。

**目标：** 玩家描述“这匹马胆小/强壮/灵活”，而不是只看到编号不同。

范围：

- 建立至少 Fast、Strong、Nervous 三种测试 Archetype。
- Speed/Stamina/Fear/Strength/Agility 真实进入运动、威胁、张力和接近计算。
- Horse Card 只展示确实影响 Gameplay 的特征。
- 毛色或灰盒颜色提供最小识别，不把视觉差异当作行为差异证据。

退出条件：

- 盲测玩家能以高于随机的准确率辨认至少三种类型。
- 同一路线与操作对不同马产生可解释的时间、张力或逃跑差异。
- 参数全部数据驱动，测试不依赖硬编码资产路径。

## P12 — 套索技巧与失控后果

**状态：已完成。** 两次增量的规格与验证见 `P12_LASSO_SKILL_SPEC.md`。

**目标：** 提高投掷技术空间，并让过载产生可读且可传播的后果。

范围按两次增量交付：

1. **已完成：** 摆绳/准备节奏、动态投掷稳定性与 Head/Neck/Torso 简化命中区域。
2. **已完成：** Rider Balance、侧向拉力、Stumble/Fall，以及可主动松手的短距离 Dragged 状态。

退出条件：

- 连续练习能提高命中率，而自动锁定不能替代提前量判断。
- 不同命中位置影响控制风险，并有清晰反馈。
- 落马和拖行由确定性阈值触发，可恢复、可调试，不破坏角色生命周期。

如果这一阶段使结果更随机或更难解释，应保留现有稳定 Solver 并回退表现复杂度。

## P13 — 垂直切片音画

**状态：前两次增量已完成，正式资源与动画待实施。** 反馈信号、程序化回退、双地表物理材质路由、Sound/Niagara 插槽、马蹄/风感/呼吸、灰盒扬尘、动态绳索风险和 Horse Card 层级已经完成，规格与证据见 `P13_AUDIO_VISUAL_SPEC.md`。

**目标：** 用必要表现强化速度、动物状态和绳索风险，形成可对外演示的灰盒增强版。

优先级：

1. **已完成基础信号：** 马蹄节奏、速度风感、体力呼吸。
2. **已完成占位事件：** 套索摆动、飞行、拉紧、危险和断裂声音事件。
3. **已完成灰盒表现：** 追逐尘土、绳索受力与控制完成反馈。
4. **待实施：** 基础马动画和骑手姿态接入；Gameplay 继续读取现有状态与动画数据接口。
5. **部分完成：** Horse Card 与命名层级已整理；任务提示和结算 UI 仍待正式化。

退出条件：

- 关闭开发 HUD 后，玩家仍能判断速度、警觉、有效张力和危险张力。
- 表现缺失或资源替换不会改变 Gameplay 结果。
- 完整 6–10 分钟流程可录制、可重复且无明显占位信息遮挡。

## P14 — 原型验证门

**目标：** 用实际玩家行为决定是否扩大产品范围。

执行：

- 至少 5 名测试者，每人完成或尝试 3 轮。
- 记录 GDD 第 8 节指标，并访谈失败原因、个体辨识和重试意愿。
- 将问题按 Blocker、Core Feel、Clarity、Polish 分类。
- 先修复核心手感和可解释性，再决定是否进入长期系统。

Go 条件：多数测试者愿意立即重试；骑乘、切出、投索和控绳各有可学习空间；失败原因大体可复述；不同马有可感知差异。未满足时继续原型迭代，不开启开放世界或经济系统。

## 验证纪律

每个里程碑都必须：

1. 在实现前写清范围、非目标和退出条件。
2. 保持 UE 5.8.2 Development 构建通过。
3. 为确定性规则添加必要测试，不用自动化替代手感验收。
4. 至少运行一条真实 Editor Gameplay 路径并保存日志/截图。
5. 更新 `DEVELOPMENT_STATUS.md`、相关 GDD 和决策记录。
