 # P14.3 测试组织者与记录指南

## 测试前

1. 给测试者分配匿名编号 `T01`–`T05`。
2. 将完整 Windows ZIP 发给测试者，要求完整解压后运行。
3. 为每位测试者复制一份 `P14.3-Session-Notes.md`；准备 `P14.3-Round-Log.csv`。
4. 告知测试者需要连续完成或尝试 3 轮，每轮结束先口述再重开。
5. 首轮允许阅读 `P14.3-PLAYER-GUIDE.md` 的启动、按键和目标。完整流程与“卡住时怎么办”可提供，但必须在 Round Log 备注中记录使用了哪条帮助。

详细教程会降低对“玩家能否自行发现操作”的测量强度，因此分析时必须区分：无协助完成、阅读教程完成、组织者现场提示后完成。教程本身是否足够清楚也是本轮可用性结果。

## 每轮同步记录

游戏在轮结束、F2 重试或退出时自动写出 JSON。人工表每轮填写一行：

- `TesterId`：匿名编号。
- `Round`：1、2、3。
- `MetricFile`：对应 `Round-*.json` 文件名。
- `Completed`：是否完成命名。
- `FailureExplanationAccurate`：玩家解释是否与事件和 JSON 一致。
- `ImmediateReplay`：询问后是否愿意立即再玩。
- `Ride/Isolate/Throw/RopeScore`：观察者按 1–5 评分。
- `HorseDescription`：玩家如何描述目标，不提示类型名称。
- `WeakestSegment`：Ride、Chase、Isolation、Lasso Throw、Rope Fight 或 Capture。
- `IssueClass`：Blocker、Core Feel、Clarity、Polish。
- `ObserverNote`：原话、卡住步骤、是否读取救援提示。

MetricFile 最好在每轮结束后立刻确认，避免三轮结束后无法对应。按修改时间排序即可找到最新 JSON。

## 观察规则

- 不替玩家操作鼠标键盘。
- 玩家完全无法继续时可以提示，但必须记录触发步骤和提示内容。
- 不评价“正确玩法”，只记录玩家做了什么、看到了什么、认为发生了什么。
- 失败后先问原因，再解释系统规则，避免污染 Failure Understanding。
- Round 3 后再进行完整访谈。

## 回收文件

让测试者在解压目录中右键 `Tools/CollectPlaytestResults.ps1`，选择“使用 PowerShell 运行”，输入 TesterId。脚本会搜索打包目录和 `%LOCALAPPDATA%/Steppe/Saved/Playtests`，只收集真人 `isAutomated=false` 的 JSON，并生成：

```text
PlaytestResults/T03/T03-PlaytestResults.zip
```

脚本默认只收集机器上最新 3 轮真人记录，因此同一台电脑可以按顺序测试多人而不会自动带入上一人的旧轮次。测试中止且不足三轮时，由组织者运行 `CollectPlaytestResults.ps1 -TesterId T03 -AllowPartial`。测试者将结果 ZIP 和填写后的 Session Notes 交回；不要让不同测试者共用同一个 TesterId。

## 汇总与研究评审

把回收的 JSON 放入开发工程的 `Saved/Playtests/`，运行：

```powershell
.\Scripts\SummarizePlaytests.ps1
```

然后检查：Retry Desire、Failure Understanding、Round 1 → Round 3 的耗时/投索/失败改善，以及 WeakestSegment 频次。15 轮齐全后才进入 P14.3 Gameplay Research Review。
