# P16.5 临时骨骼马素材

## 来源与存放

临时马来自 Quaternius 的 [Ultimate Animated Animals](https://quaternius.com/packs/ultimateanimatedanimals.html)，许可为 [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)。本机下载原件完整保存在 `ThirdParty/Quaternius/UltimateAnimatedAnimals/Source/`，不进入 Unreal Content、不提交 Git、不打入玩家包。仓库保留 `ThirdParty/Quaternius/UltimateAnimatedAnimals/LICENSE.txt` 记录来源与许可。

实际游戏资源位于 `/Game/Steppe/ThirdParty/Quaternius/AnimatedAnimals/Horse/`。这里存放由 `Source/Model/glTF/Horse.gltf` 导入的 Skeletal Mesh、Skeleton、材质和 13 段 Animation Sequence。

## 当前接入

所有 `ASteppeHorseCharacter`，包括坐骑和野马，共用该骨骼网格。网格在角色中按 0.45 缩放、旋转 -90°、下移 94 cm；仅作为视觉组件，关闭碰撞和重叠。现有 Capsule、HorseMovement、AI、套索命中体积、骑乘与牵行规则保持原状。旧的 16 部件灰盒马保留为资源缺失时的回退，并在骨骼网格有效时隐藏。

`HorsePresentationComponent` 按已有 `AnimationData.Gait` 选择 `HorseIdle`、`HorseWalk` 或 `HorseGallop`，仅在步态切换时调用 `PlayAnimation`，并按实际速度调整播放速率。旧版仅为 Blend Space 指定资源和速度，却没有验证最终骨骼姿态；用户实际试玩发现马匹平移而腿不动。现已撤掉该 Blend Space，自动化测试直接比较游戏运行期间前腿骨骼的两个姿态，确保真实旋转。网格设为 `AlwaysTickPoseAndRefreshBones`，避免可见性裁剪造成骨骼更新停止。当前没有独立的小跑/慢跑片段，步态切换仍是临时硬切；跳跃、惊吓、受力和倒地尚未接入动画状态机。Fast、Strong、Nervous 的毛色通过导入材质的 `BaseColorFactor` 动态参数区分。

## 重建与验证

已提交的 `.uasset` 足够打开和打包项目，不需要重新导入。只有在清空这些资源并保留原件后，才运行：

```powershell
.\Scripts\RunEditor.ps1 -PythonScript 'D:\development\Project STEPPE\Scripts\ImportTemporaryHorse.py' -LogName ImportTemporaryHorse
```

首次 Interchange glTF 导入已生成并保存 24 个资源，但命令行编辑器在导入后的退出阶段发生一次崩溃；随后独立进程成功重新加载网格、Skeleton 和 Idle/Walk/Gallop，并采样到 Walk/Gallop 的骨骼位置及旋转变化。因此以独立重载、编译、自动化测试、渲染和打包结果作为验证依据，不把那次导入进程退出当作导入成功证明。

P16.5 首轮只检查了动画资源指针，未发现骨骼不动。修复后的 P1 世界测试检查骨骼网格、灰盒隐藏、Idle/Walk/Gallop 选择，并比较行走时前腿骨骼的旋转。使用实际 `BP_SteppeHorse` 的渲染 Smoke 在疾驰时记录 `HorseGallop`、706.3 cm/s 和 48.772° 前腿跨帧旋转。24 项自动化回归、三匹野马专用渲染与完整捕获/牵回/命名 Smoke 通过；Windows Shipping 重新构建并通过启动检查。仍需玩家观察骑乘视角、步态节奏和套索命中区与可见头颈的对应。

## 下一步

这只是视觉替代素材。下一轮应在同一骨架上增加起步/停步、转弯、受力、落马与骑手姿态，并用骨骼 Socket 或附加定位点复核 `RiderSeat` 和套索命中体积。正式美术替换时保留角色 Gameplay 接口，不让动画位移改写马匹运动。
