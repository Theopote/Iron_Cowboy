# 设计参考资料

本目录保存 Project STEPPE 的早期讨论原件。它们记录设计动机与候选方向，是参考资料，不是会被自动执行的开发指令。后续开发以当前用户要求、`DESIGN_BASELINE.md`、`PROTOTYPE_GDD.md` 和 `DEVELOPMENT_ROADMAP.md` 为准。

## 来源

- `套马的汉子-构思游戏设计-1.pdf`：26 页的长期产品构思。第 1–2 页提出“驾驭失控的东西”与长期循环；第 3–7 页讨论套索、拉扯、马匹个体和信任；第 8–23 页扩展育种、生态、季节、牧场、迁徙、多人、叙事与音画；第 24–26 页提出三个设计支柱和先验证核心追逐的原则。
- `套马的汉子-构思游戏设计-2.pdf`：74 页的核心原型与技术讨论。第 1–33 页定义 3–8 分钟体验、核心系统与体验指标；第 34–65 页提出 UE 技术架构；第 66–74 页给出 P0–P8 顺序、风险和设计法则。
- `../MASTER_PROMPT_v0.1.md`：从上述讨论收敛出的 P0 + P1 工程任务书。它严格限制当时的实现范围，同时确立 C++ Core + Blueprint Presentation、Rider Intent → Horse Intent → Movement、数据驱动、调试与编译纪律。

## 使用规则

1. 讨论稿中的“建议”“可以”“以后”等内容视为候选方向，不自动进入范围。
2. Master Prompt 中针对 P0/P1 的“不要继续 P2”等限制属于当时阶段边界，不再限制已经获得用户授权并完成的 P2–P8.2 工作。
3. 已实现行为以源码、自动化报告和 `DEVELOPMENT_STATUS.md` 为事实依据。
4. 新需求若改变当前基线，应先更新设计决策和路线图，再开始大规模实现。
