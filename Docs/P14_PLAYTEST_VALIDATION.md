# P14 原型验证与试玩数据规范

## 目标

P14 用真实玩家行为判断当前核心闭环是否值得继续扩展。工程自动记录客观事件，观察者补充玩家是否理解失败、能否辨认马匹差异以及是否愿意重试。自动数据用于定位问题，不代替手感判断。

## 已接入的自动记录

每次进入关卡开始一轮记录，并在成功、超时、F2 重试或世界结束时写入 `Saved/Playtests/`。正常试玩使用 `Round-<UTC 时间>.json`；自动验证使用固定的 `P14-Success.json` 和 `P14-Failure.json`。

| 分组 | 字段 | 含义 |
| --- | --- | --- |
| 结果 | `result` / `endReason` | Success、Failed 或 Abandoned，以及命名完成、时间耗尽、重试或世界结束 |
| 身份 | `targetHorse` / `targetArchetype` / `hitZone` | 本轮首次选中的目标、类型及首次附着区域 |
| 阶段 | `stageSeconds.*` | 选中、切出、捕获、接触、交付和命名相对本轮开始的秒数；未到达为 `-1` |
| 操作 | `throws` / `attachments` / `misses` | 出手、附着及脱靶/遮挡/目标丢失次数 |
| 绳索 | `ropeBreaks` / `releases` | 断绳和主动/流程松绳次数 |
| 风险 | `dangerousTensionEntries` / `peakTension` | 进入危险张力的次数和峰值 |
| 事故 | `balanceWarnings` / `falls` / `dragged` / `peakBalanceRisk` | 平衡预警、落马、拖行和归一化最高失衡值 |
| 总结 | `elapsedSeconds` / `score` / `retries` | 本轮耗时、积分及因重试结束的次数 |

计数依据状态跃迁而不是帧数。同一段持续危险不会被每帧重复统计；投索从飞行直接进入附着时仍只计一次；断绳与普通脱靶分开统计。

## 人工试玩计划

至少 5 名测试者，每人连续尝试 3 轮。首次试玩不给完整操作演示，只说明目标和基础按键；观察者不在操作中纠正，除非玩家完全无法继续。

每轮结束后记录：

1. 玩家用自己的话描述成功或失败原因。
2. 不看开发 HUD，玩家是否能判断马的警觉、有效张力和危险张力。
3. 玩家认为目标属于快速、强壮或紧张中的哪类，以及判断依据。
4. 是否愿意立即再玩一轮；若否，记录最主要原因。
5. 一个最想调整的手感或信息问题。

将自动 JSON 和访谈记录用匿名测试者编号关联，例如 `T03-R2`。不要在记录中保存姓名或联系方式。

## 首轮分析规则

- **Blocker：** 无法完成、卡死、输入丢失、重试不能恢复或数据未写入。
- **Core Feel：** 骑乘、切出、投索、控绳的结果与玩家输入关系不清晰。
- **Clarity：** 玩家能操作，但无法判断目标状态、风险或失败原因。
- **Polish：** 不妨碍理解与重试的画面、声音和过渡问题。

优先比较同一测试者第 1 轮与第 3 轮：投索次数、脱靶/断绳、阶段耗时是否改善。不同马类型分别汇总，避免将 Strong 的较长控制时间误判为普遍节奏问题。

## Go 条件

完成至少 15 轮人工样本后再作决定。多数测试者愿意立即重试；大多数失败原因可以准确复述；第 3 轮较第 1 轮显示可观察的学习；三类马能被行为描述。未达到时先修 Core Feel 和 Clarity，不扩大地图、马群规模、经济或长期养成。
