# Project STEPPE 设计决策记录

本文件记录会影响多个系统或后续范围的长期决策。实现细节仍写在对应阶段文档和 `ARCHITECTURE.md` 中。

## D-001 — 使用 UE 5.8.2

**状态：已确认**  
本机与项目以 Unreal Engine 5.8.2 为目标。只有出现明确的引擎缺陷或资源兼容阻塞时才重新评估版本，不为单个素材改写核心架构。

## D-002 — C++ Core + Blueprint Presentation

**状态：已确认**  
C++ 持有确定性状态、运动、AI、套索判定、任务与测试；Blueprint/资产承担动画、音频、VFX、UI 表现和快速调参。视觉资产不能成为 Gameplay 判定权威。

## D-003 — 意图与运动分层

**状态：已确认**  
玩家输入形成 Rider Intent，骑手或 AI 形成 Horse Intent，Horse Movement 再根据惯性、体力和环境产生实际运动。不得让 Controller、AI 或动画直接设置最终运动结果。

## D-004 — 附近马群使用完整 Actor

**状态：已确认**  
原型优先验证行为，当前 5 匹野马均为完整 Actor。达到可玩性目标并出现实际性能需求前，不引入 MassEntity 或多级远距离模拟。

## D-005 — Gameplay Rope 与 Visual Rope 分离

**状态：已确认**  
长度、张力、附着、断裂和捕获由可调试的 Gameplay Solver 决定。Cable、Chaos、骨骼或粒子只表现结果，未来可以替换而不改变规则。

## D-006 — 早期讨论稿是参考资料

**状态：已确认**  
两份构思 PDF 包含大量长期候选方向，不构成自动开发清单。Master Prompt 的阶段限制只约束当时的 P0/P1 执行。当前基线文档和用户最新要求决定近期范围。

## D-007 — 保留工程里程碑历史，重新解释完成度

**状态：已确认**  
不重命名已经完成并留有测试证据的 P0–P8.2。文档明确说明：工程 P7/P8 只完成了早期同名阶段的一部分。P9 已补齐安全接近与第一次接触；P10 继续补齐牵回、营地交付和命名。

## D-008 — 下一目标是 6–10 分钟完整闭环

**状态：已确认**  
当前 120 秒挑战继续保留为快速测试模式。产品验证目标扩展为营地出发、捕获、安全接近、牵回和命名的 6–10 分钟流程；通过重复游玩验证后再考虑长期系统。

## D-009 — P9 成功判定延后到第一次接触

**状态：已替代（由 D-010）**
按 C 仍立即登记绳索捕获，但任务计时和成功结算持续到 `FirstContact`。这样安全接近是任务的一部分，玩家不能通过按 C 跳过 P9。计分仍使用已捕获数量和完成第一次接触时的剩余时间。

## D-010 — P10 命名完成本轮，名字暂不跨局保存

**状态：已确认**
任务计时从 P9 的 FirstContact 继续延后到 `Named`。Horse Card 接受 1–16 个字符并只在当前 World 生命周期保存；F2 重玩会清除名字。先验证牵回和命名是否形成值得重复的闭环，再决定 SaveGame 结构。

## D-011 — P11 使用三种确定性、可编辑原型

**状态：已确认**
HerdManager 按成员编号确定性分配 Fast、Strong、Nervous，并通过可编辑 Profile 将倍率应用到实际 Gameplay 组件。灰盒颜色和 Archetype 标签只帮助识别，不能作为行为差异的判定依据。确定性分配让试玩对比、自动化和问题复现使用同一基线；未来可将 Profile 迁移到数据资产而不改变消费接口。

## D-012 — P12 投掷技巧使用确定性稳定窗口

**状态：已确认**
RMB Aiming 形成可预测的摆绳周期，LMB 出手锁定 Stability，并缩放环口、速度和射程。系统不增加随机散布，也不把方向自动吸附到目标。灰盒命中区先按局部高度划分，Neck 为稳定基准，Head 提高张力风险，Torso 延长控制时间；接入骨骼模型后只替换分类来源。

## D-013 — 落马是可恢复的状态转换

**状态：已确认**
Rider Balance 由张力、侧向比例、速度、目标 Strength 和命中区确定性计算。落马只解除骑乘关系并交回 CharacterMovement，不销毁 Actor 或引入生命值；拖行严格限时 1.25 秒，玩家可随时 LMB 松绳。先验证风险是否可读、失败是否促使玩家改线，再决定伤害、布娃娃或更长后果。

## D-014 — 音画反馈只读取 Gameplay 状态

**状态：已确认**
Rider 上的 SteppeFeedbackComponent 在既有 Gameplay 组件之后派生步频、风感、呼吸、绳索压力与离散事件，不写回运动、套索、Balance 或任务规则。第一增量使用运行时生成的短 PCM 和灰盒扬尘，避免引入来源不明的临时素材；后续正式声音、Niagara 和动画通过同一信号接口替换。

P13.2 将地表也作为只读表现输入：Physical Material 只选择 Grass/Hard 声音与粒子，不修改马匹运动。正式 SoundBase/NiagaraSystem 通过可编辑资源插槽覆盖程序化回退，资源缺失不会改变状态机或阻塞测试。
